# OSStack delegated method

Read the parent brief, relevant user constraints and [common evidence rules](../../references/evidence.md). Confirm the actual base revision or input identity, required outcome, allowed files/resources, and checks. Resolve ordinary choices within the delegated scope; do not repeatedly seek approval already supplied. Report a missing ownership boundary before touching shared state, while continuing independent read-only work.

Apply the coordinator's agreed design and acceptance checks to your assigned slice. Planning or delegation guidance inside a method does not expand your write boundary or permit spawning more workers; report cross-slice needs to the coordinator.

Choose the relevant shared method:

- [Task framing](../../references/task-framing.md) for a requested restatement or refined prompt; executing the framed task requires authority already present in the brief.
- [Performance measurement](../../references/performance-measurement.md) for comparable work, trustworthy timing and bounded performance conclusions within the delegated task.
- [Change impact](../../references/change-impact.md) for affected consumers, hidden contracts and tests of critical safety assumptions within the assigned boundary.
- [Code review](../../references/code-review.md) for a bounded review with concrete findings and evidence; apply fixes only within the delegated authorization.
- [Feature](../../references/feature.md) for an owned implementation slice with observable acceptance checks.
- [Refactoring](../../references/refactoring.md) for structural changes under a pinned behavior contract.
- [Investigation](../../references/investigation.md) for a cited explanation or assessment.
- [Bug fix](../../references/bug-fix.md) for an authorized correction and same-surface recheck.
- [Create verification](../../references/create-verification.md) for a repeatable driver/feature-map procedure.
- [Maintain verification](../../references/maintain-verification.md) for drift and harness corrections within their assigned scope.

Other assigned engineering work follows the host's normal supported workflow; do not claim a missing OSStack playbook is present. Use the exact material version supplied by the coordinator. If a required reference is inaccessible, name the attempted path and impact rather than silently selecting another installed version.

Keep writes inside the assigned boundary. Treat another worker's uncommitted files and live resources as theirs. A discovered cross-boundary defect is a finding to hand back, not an implicit expansion of ownership. The coordinator owns integration, shared ledgers and the overall plan unless the brief explicitly delegates those responsibilities. Further delegation uses real host tools only when authorized and available; do not spawn a second coordinator simply to run this wrapper.

Return the inspected candidate, actual changes or findings, checks with raw evidence pointers, failed attempts, and remaining resource/cleanup obligations. Distinguish your own observations from prior reports and from unexecuted recommendations. Do not mark the parent task complete or publish changes outside the brief's existing authority.

This skill can guide a real delegate, but loading it does not create a process, register an agent type, authenticate a principal, prove independence or grant a MethodBinding. The actual host remains responsible for spawning and permissions.
