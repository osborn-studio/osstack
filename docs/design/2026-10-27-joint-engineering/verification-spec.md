# 验证协议与独立证据

## 1. 证明范围

| 结论 | 判定依据 | 不能替代的东西 |
|---|---|---|
| 来源理解 | 固定源码、原始测试、作者原文、语义差异 | 不能只读二手摘要或模型意见 |
| 文档可执行 | 来源/依赖/映射/schema 正负例 | 不能宣称运行时正确 |
| 机制正确 | 实际边界契约、独立模型、故障与变异 | 不能只镜像实现写测试 |
| 集成正确 | 同一个组合候选上的联合旅程 | 两条分支分别 CI 通过不够 |
| 用户价值 | 固定预算的对照、冷使用者、完整分母 | 单次顺利演示不是收益证明 |
| 环境资格 | 具体 host/provider/adapter/隔离版本实测 | 本地可信用户不能认证恶意同 UID 或远端 |

69 个 `JA*` 场景在 acceptance-cases.json 中给出 Given/When/Then、坏变体、oracle、层级、负责人。它们都是 **specified_not_run**。这里的可执行指：实施者能确定构造什么输入、执行哪个边界、观察什么结果、什么变化应导致失败；本轮不声称已拥有这些产品测试实现。

## 2. 测试层级和工具

1. 纯协议：严格 schema、身份、角色映射和版本；Python/jsonschema 检查本设计 fixture，产品实现后由 Zod/Vitest 验证同一语义。
2. 实际接口：测试真实 `method-admission → context wrapper → raw adapter`；不能只测 renderer，也不能只借旧 host 的拒绝测试声称新增入口安全。
3. 独立状态模型：只包含权威、义务、预算和可观察效果；通过事件序列比较，不能复制实现分支。可采用 fast-check commands/asyncModelRun；保存 seed 与最小失败序列。
4. 故障注入：在 intent 持久化、授权消费、外部启动、receipt 持久化、cleanup、迁移启动等边界注入退出、I/O 错误或断连。process kill 不等于物理断电；后者单独环境验收。
5. 变异：删除 fence、忽略 contract/method/candidate digest、丢 required artifact、重复释放预算、unknown 自动重试、observed_turn→done、dry-run 写 DB。每个坏变体必须由相关测试杀死；没有杀死则不能用该测试支持对应保证。
6. 联合旅程：通过真实入口、实际 host 和受控 Provider 或明确标注的测试 Adapter。fake 与 live 两类结果分开，不互相替代。
7. 形式化：仅对 owner/dispatch/cancel 等高后果不变量建有界模型，TLC 运行参数、完整结果、坏变体和源码映射齐备。画图或解析器成功不计通过。

差分测试只用于声明要保持的行为。Firstmate Shell 与 OSStack TS 不要求逐字输出相同；比较“问题不丢、未知不重发、权限不扩大”等观察，并对 OSStack 更严格的差异预登记。

官方方法依据：[fast-check 模型测试](https://fast-check.dev/docs/advanced/model-based-testing/)、[Git merge-tree](https://git-scm.com/docs/git-merge-tree)、[GitHub 合并队列](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-a-merge-queue)。这些工具在本轮未安装或配置到产品。

每个实现 PR 的 evidence manifest 至少记录：候选 SHA/tree、依赖 SHA、源码/构建摘要、schema 与 profile、工具版本、命令与退出码、原始日志位置与 hash、条件跳过理由、场景结果。hash 不独立认证执行者；可信 CI 或独立复跑提供第二来源。

## 4. 产品实验预登记

本节阈值是**拟议决策规则**，不是已有收益或统计结论。运行前由 evaluation-owner 冻结任务集与协议版本，变更必须开始新实验批次。

### E0：工具/材料可行性

以 3 条命名路径和固定合成缺陷验证：冷调用者能运行工具、必需材料到达实际 adapter、原表面可复现。任一关键边界失败先修工具；不开始大规模 recipe 平台。

### E1：方法增量 A/B

先做 12 个独立任务的配对可行性试验，覆盖复现修复、跨文件行为、模糊假设、环境故障四类；两种条件随机顺序、各用干净工作区，固定模型/版本/权限/工具/预算。每次最长 30 分钟，固定调用预算另登记；不能达到配额则记录 truncated，仍计入分母。该样本只用于发现明显问题与估计波动，不作确定 ROI 结论。

baseline 是当前 OSStack，P 只增加本次方法与验证材料。共享驱动若属于两组必需测量设施，两组都使用；另记工具成本，不能只给实验组更好的环境。

### E2：联合四组

在 J16 后比较 baseline、F、P、F+P。F 仅开本次新主控/监督增量；当前 main 已有的 Firstmate 行为四组一致保留。P 仅开本次方法增量。固定同一二进制的受控开关，若无法在相同条件隔离，记录混杂因素，停止声称单独因果效果。

探索批建议 40 个独立任务、每条件两次重复，任务类别事先分层；预算不足先报告已有样本，不临时挑任务。任务级配对统计，重复运行不能当作独立任务数。给出完成率差、人工干预数、墙钟与费用分布及任务级区间；组合交互可报告 `(F+P - F) - (P - baseline)`，同时报告误差。是否足够做默认启用决策由预登记最小有价值效应与不确定性决定。

### 指标和门槛

- 主指标：在合同与隐藏验收下完成的任务比例。包含超时、失败和环境不可用的全部尝试；环境问题另分层，不从总分母删除。
- 保护指标：无依据完成、未授权效果、重复效果、丢失决定。任一可复现事件立即暂停相应新自动化，修复后新批次验证；“样本中零次”不是风险绝对为零。
- 次指标：人工干预次数、恢复步骤、耗时 p50/p95、模型/工具费用；unknown 费用不得当零。
- 拟议继续阈值：完成率至少提高 5 个百分点，或完成率不明显下降且人工干预至少下降 20%；同时 p95 耗时与单位成功任务成本不超过基线 1.2 倍。区间跨越退化/收益门槛则结果不确定，保留 opt-in 并收集更多样本。
- 缩减条件：收益只出现在某一任务类型，限定该方法/路由；没有收益且额外成本明显，则停止扩展四类 recipe、动态 swarm 或全自动启用。

上述数值是本设计提出的可调整预算与产品决策阈值，必须在看结果前冻结，不能事后调整来制造胜利。

## 5. 独立判定和审查

任务作者不能修改隐藏验收器。reviewer 不只读取作者摘要，而读取实际 diff、产物和日志。人工冷使用者按文档复现，不由实现 Agent 在背后补步骤。模型审计记录实际模型元数据、输入版本、原文与逐条处置；不同提示词的同一模型不是跨模型独立共识。

固定 transcript 语义评估至少包括：用户假设错误、问题缺关键上下文、只读调查、原型否定首选设计、报告声称已验证但无对应证据。JSON 字段齐全只通过结构层；语义有争议则记 uncertain，交给独立判定，不强算成功。

## 6. 本轮与未来的边界

本轮只执行文档验证、schema/fixture 正负例、源 hash/输入完整性和范围检查。不执行产品测试、上游全套测试、真实 Provider、正式原型、四组实验、迁移或发布。具体输出见 validation.md；旧报告中的测试数量仍绑定原候选。
