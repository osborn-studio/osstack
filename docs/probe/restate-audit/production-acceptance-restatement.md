# Restatement: Evidence Required for Probe Production Acceptance

Probe should be accepted for production only after its operating evidence, not
merely its implementation and tests, demonstrates that the rollout is sound.

The release under evaluation must be the version used by both the installed
CLI and the stable daemon. The supported Probe skill installation must be
available, and the repository must keep an explicit report-mode policy plus a
portable, manifest-validated session record.

Observation must cover fourteen actual elapsed days. During that interval,
Probe in report mode must never prevent unrelated repository work from
continuing. At least five genuinely early-stage product or technical specs
must traverse the skill-led, one-question-at-a-time workflow, with every
dynamically introduced item backed by repository evidence.

A person must inspect restatement findings and determine that wording changes
are not being systematically mislabeled as meaning changes. The owner may
freeze an outcome baseline only when the collected results justify doing so;
otherwise the observation period continues.

Bootstrap work may establish report mode, a durable first session, and
portable output. It cannot switch on blocking enforcement, supply owner
answers, manufacture elapsed time or completed tasks, or close design
checkpoints whose evidence is still missing.
