A long token stream retains all these Promise.race closures until the invocation dies. Replace with a bounded wait subscription that unregisters on settlement (e.g. a Set of active waiter callbacks), so the number of waiting cancellation callbacks is proportional to active operations, not total streamed events. Keep existing late-rejection handling and listener tests.
2. Once invocation has begun, executor exits on malformed terminal/work-after-terminal/iterator exceptions must not merely schedule `iterator.return()` and clear the timeout while owned work can continue. Confirmed failure must remain failed. Return promptly even if iterator.return never settles. A test adapter should emit invalid/post-terminal work, retain an active side-effect flag until the signal is received, and have a hanging return; assert signal delivered and unconfirmed stop visible. Distinguish original failure from cancellation failure: G04 must gate on cancellation.stop_confirmed=false, not only one failure_code string.

Avoid claiming that stopping iterator consumption proves remote/process work stopped. Preserve ordinary terminal error/done(failed) stream compatibility when it closes normally. No future action ledger or graph scheduler implementation here.
