# PR291 runtime header network follow-up

The Node20.6.0 Linux job failed while receiving the official headers response body: HTTP200 was followed by TLS abort/connection reset. The original log is preserved in `original-ci.log.gz`. This is direct evidence of that network failure; it does not establish a product defect or a successful replacement CI run.

The bounded preparer fetches the current runtime's exact stable version from the fixed official Node HTTPS origin. Each file has at most three attempts, each with a 60-second deadline covering connection and the entire response body. Request and response sockets are explicitly destroyed on success/error/deadline; data from failed attempts is discarded. Response size is bounded. Nonretryable HTTP failures and SHA mismatches fail closed. Only SHA256-matching archive bytes reach tar; tar listing/extraction each have 30-second limits. The extracted version and NODE_MODULE_VERSION must match the running process before a verified receipt is written. Failed owned directories remain for diagnosis; existing output is never overwritten.

CI supplies this verified directory through `--nodedir`. The pinned [node-gyp v11.5.0 configure source](https://github.com/nodejs/node-gyp/blob/v11.5.0/lib/configure.js) selects the local directory and bypasses its install/download branch. Its [versioned README](https://github.com/nodejs/node-gyp/blob/v11.5.0/README.md) describes using the headers' config.gypi. Checksums come from the exact release's official SHASUMS256.txt over HTTPS; this is a transport-pinned official checksum check, not an additional signature claim. Runtime versions, ABI checks and graph tests in the matrix are unchanged.

The final 14 tests pass. They exercise real loopback HTTP and real tar archives, including HTTP503 recovery/exhaustion, HTTP404, truncated response, stalled body, checksum mismatch, version/ABI mismatch, duplicate checksum entries, existing output and size rejection. A real child exhausts three body deadlines then exits naturally; a parent timeout or kill fails the test. The standalone scratch helper mirrors the canonical root/layout/label rules in `packages/core/src/scratch.ts`, including relative environment resolution. Cleanup is registered before fixture setup.

The current script also actually downloaded and verified official Node22.22.1 headers on macOS arm64 (ABI127). Its receipt and official checksum list are preserved. This does not stand in for Linux20.6.0/22.23.1 CI or a fresh native SQLite build. No full suite ran for this infrastructure-only iteration; the parent owns subsequent CI and audit.

Historical failures remain explicit: the first fetch-based design hung during compound stalled-body retries; a Promise.race intermediate passed but was replaced with native request/response destruction to cover process liveness. A later child-test import typo failed one test and was fixed before the final 14/14 run. See `binding.json` for exact source SHA256, code SHA, commands, outcomes and limits. Gzip files retain raw logs. `manifest.json` binds every payload except this README and the manifest itself. The full downloaded tarball remains in scratch; its SHA256 is in the preserved receipt.
