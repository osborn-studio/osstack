# Bounded G25 process interface

GraphRuntime remains the trusted host boundary. New observeWorkerProcess({ scope, graphRunId, generation, owner, identity }) reads durable launch state, validates the exact binding, and performs read-only independent OS observation. It never signals, resumes, releases resources, or grants recovery. G15 remains sole recovery authority. Return separates leader observation from executor effects (always unknown for opaque adapters), with recovery held.

GraphProcessJournal adds append-only observations referencing existing immutable graph_worker_launches. The existing launch row remains durable intent/generation consumption, written synchronously before registration/spawn. New launch observation records PID, assigned isolated PGID, captured OS identity, binding/program identity before sending init. Terminal spawn_failed (including consumed registration failure), true child exit, and bounded timeout are distinct observations. No persistence in delayed promise handlers; synchronous manager lifecycle callbacks keep DB lifetime bounded to worker events, with runtime drainage extended if necessary.

GraphWorkerStart gains optional trusted synchronous lifecycle callbacks for launch and observations. Runtime always supplies them. Linux identity uses boot id + /proc stat starttime, plus PGID. macOS captures ps lstart via execFileSync argv but explicitly marks it coarse/unverifiable; same-second identity cannot authenticate a surviving PID. Independent observation reports unknown on coarse identity, mismatch/reuse, missing launch identity, permissions/errors. Linux exact leader absence/exit does not establish descendant or external executor quiescence. No independent signaling API is added. Detached process groups isolate workers; existing direct child termination remains direct-child-only and is never evidence of executor stop.

Tests: real subprocess launch ordering and OS observation, fake reuse, timeout vs late exit, consumed registration failure/reopen, immutable program identity, host SIGKILL while worker/descendant lives. No public recovery API, docs edits, commits, or full suite. Existing manager and chain regressions targeted. Platform gaps will be explicit in process-report.md.

Review feedback accepted: additionally own graph-recovery.ts and its focused tests for the parent's requested not_started gate. A consumed graph_worker_launches row requires matching durable spawn_failed event (run/generation/owner/program identity/evidenceRef/confirmedAt), with no contradictory launched/exit/timeout events. Legacy synthetic trusted-verifier tests without consumed launches stay unchanged. The DB drainage barrier now includes each worker finalExit, because late OS observations write SQLite.
