## G07 supervisor codec review (implementation snapshot)

Concrete issue to reproduce before fixing: opt-in Uint8Array values can shadow `buffer`, `byteLength`, `byteOffset` or `length` with own getters. encode currently reads bytes.buffer before rejecting extra properties; decode reads data.buffer/data.byteLength too. Those getters execute despite the no-hook contract. Use captured intrinsic TypedArray getters (from Object.getPrototypeOf(Uint8Array.prototype)) for buffer/offset/length, and reject extra own properties for encoded byte values before any ordinary property reads. types.isUint8Array should reject a forged Object.create(Uint8Array.prototype) before touching internals. Add regression tests with getter invocation counters for encode and raw-byte decode; ordinary Buffers as raw wire can remain supported through intrinsic slots. Keep shared buffers rejected. This is a narrow codec correction, not new product scope.

## G07 final transport projection check

Please inspect list(input, options): unlike getTuple/put/putWrites, it appears to serialize the entire RunnableConfig rather than project only thread_id / checkpoint_ns / checkpoint_id. A real RunnableConfig can carry callbacks/functions/tags/runtime objects, so history reads with callbacks may fail despite the decision saying only durable identity crosses the wire. Reproduce via contract list with a callback function, then project the identity fields while preserving omitted-field wildcard semantics. A callback must not be serialized or invoked. This is within the list public-Saver contract. Supervisor will add the codec package subentry after your final scope check; do not change package exports concurrently.
