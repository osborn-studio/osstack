# Next pstack delivery selection

Baseline: `4afffbb150d0e106db08f7b4ed64ed07af8861d2`. This is a read-only proposal, not an implemented feature, bug confirmation, gate or model-use result. No tests, models, DB or forge requests were run. Source byte bindings are in `selection.json`.

## Recommend: one-shot explicit stack candidate report

**User outcome:** one invocation answers “which PR is the next unresolved item in my declared stack, what do we actually know about it, and which upper PRs remain dependent?” It retains the existing per-PR evidence instead of requiring the user to reconcile several JSON folders manually. For the real 308→309 workflow, upper green checks cannot replace lower merge; after lower merge, an upper base still pointing to the old parent is reported for its owner to reconcile. Numbers in this example are historical context, not a claim about their current forge state.

**Current gap is a new feature, not an old bug:** `scripts/report-pr-candidate.mjs` accepts one `--pr`; `inspectPrCandidate` brackets one PR's facts. `ingestStack` accepts several numbers but reconstructs topology from branch names and has neither the snapshot's SHA bracket nor review-thread observations; CLI ingestion writes local cards. Existing cards are intentionally skipped and are not fresh forge evidence. Do not modify that idempotence or reinterpret `detectDrift.clean` as a merge gate. The queue explicitly leaves the PS17 stack-frontier path unconnected.

**Minimal interface:** `inspectPrStackCandidate(input, runner?, clock?)` wraps the existing collector, without changing its classifier. A closed, ≤64 KiB plan supplies one repository, an ordered list of 1–3 unique PRs (bottom-to-top), the intended target branch, and optional per-PR expected head/base SHA pairs and required check names. The CLI is `node scripts/report-pr-stack-candidate.mjs --plan /owned/stack-plan.json --output /owned/scratch/runtime/stack-NEW`. A root-level alias/barrel is integration work, not another method or runtime. Output is new under the existing scratch discipline: a compact JSON/Markdown report plus each original snapshot/query/raw record and a manifest. No overwriting or DB writes.

**Selection rules to freeze before implementation:**

1. Preserve caller order; never infer precedence from numerical PR IDs. Collect each PR at most once, serially, using the existing bracketed collector and read-only runner. Cap at three PRs / 24 requests / 270 seconds of collection budget; no retries or polling. If the overall remaining budget is insufficient, mark remaining rows `not_observed`, not empty success. Timeout enforcement remains the actual runner's responsibility.
2. Only an observed, internally stable `MERGED` prefix can be passed over. The first non-merged row is the *observed frontier*, regardless of whether its CI is favorable. If its identity is unavailable or changed, return `frontier_unknown`; do not skip it and promote the next row. `CLOSED` without merge is `closed_unmerged`, not completion. All stable merged rows produce `observed_all_merged`, never a command to merge.
3. Display every row's independent blockers, waiting reasons, unknowns and completeness. Required names remain caller-declared. Neutral/skipped remain the snapshot's unknown policy. Unknown review/forge policy stays unknown. A selected frontier is not Ready; `merge_authorized` is always false.
4. Report branch relation separately from frontier selection: an open upper row whose base matches its predecessor's head has the observed declared dependency; otherwise mark the relation unconfirmed or inconsistent. For the frontier following a merged prefix, compare its base branch with the caller's intended target and report `retarget_review_needed` if different. Do not rewrite a branch or claim its commits are incorporated. A name match is not ancestry proof.
5. Include every observation time and head/base bracket. Several individually stable reads do not prove an atomic stack snapshot, and a parent can merge after its observation. The report is dated evidence, not a current lease. No automatic repeated read, advancing watcher or merge authority is added.

**Exclusive implementation proposal:** new `packages/github/src/pr-stack-candidate.ts` and `.test.ts`; new `scripts/report-pr-stack-candidate.mjs` and `.test.mjs`; `docs/implementation/pr-stack-candidate/README.md`. Root owns export/alias/CI and shared method links if adopted. Reuse `inspectPrCandidate`/`DeliveryCommandRunner` and existing scratch/evidence patterns; do not copy its check classifier or create a generic policy engine.

**Meaningful acceptance:** frozen offline runner observations for (a) lower open failing + upper green, (b) merged prefix + open child correctly retargeted, (c) merged prefix + child still based on old parent, (d) unavailable/changed lower + upper green, (e) closed-unmerged lower, (f) all merged, (g) reversed/unconfirmed declared branch relations, (h) missing/ambiguous required checks and skipped/neutral, (i) later query timeout retaining earlier evidence and marking unobserved rows, (j) invalid/duplicate/>3 plans making zero queries, and (k) output collision and unsafe parent rejection. Assert no mutation argv, original per-PR facts and hashes retained, and simultaneous blockers/unknowns survive rendering. A separately authorized final live read of a caller-selected pair is useful; no model budget is required. Never claim that offline fixtures establish current forge status.

**Dependencies:** #307 provides the singleton collector already merged in the baseline. #308/#309 stack-mapper fixes are separate and not required for this new wrapper; do not wait for their merge to implement this slice if root authorizes it. Source integration should still start from the actual latest main and avoid importing unpublished stack changes. Exact current PR state and branch protection remain runtime observations, not assumptions from this plan.
