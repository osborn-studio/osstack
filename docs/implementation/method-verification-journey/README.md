# Fixed method verification journey

This tool turns the existing skills-check driver into a reusable two-feature journey. It runs doctor, runs healthy and missing-ref against real local Git fixtures, verifies retained evidence, and writes a two-row feature map. It does not invoke a model or claim native skill selection.

After the normal frozen install and build, select a new absolute output directory beneath the resolved scratch root (`OSSTACK_SCRATCH_ROOT`, or the platform temporary directory plus `osstack`). Its parent must exist. For example:

```sh
export OSSTACK_SCRATCH_ROOT=/absolute/scratch/osstack
mkdir -p "$OSSTACK_SCRATCH_ROOT/runtime"
node scripts/method-verification-journey.mjs --output "$OSSTACK_SCRATCH_ROOT/runtime/new-journey"
```

The command refuses existing output, including symlinks. It writes only the newly owned output tree. The actual driver receives a minimal environment, explicit isolated OSSTACK_HOME and its own scratch root. No default database, user Git repository, global host settings or live provider is used. The output contains raw doctor/driver stdout, stderr and exit records, the original per-case evidence directories, `journey.json`, `journey-manifest.json` and `feature-map.md`. Evidence survives fixture removal. Failed cases with a retained manifest keep its digest marked unverified; uncreated or unsealed evidence is labelled as such rather than linked to a nonexistent manifest. Refusal before acquiring the new output directory creates no failure artifacts. Failure stops the remaining case and preserves existing evidence; use a new output for a later attempt.

Healthy requires product exit 0. Missing-ref requires product exit 1 and an unreachable ref; this source has not recovered. The underlying driver exits 0 when the expected result, input preservation and its cleanup predicates pass. This wrapper additionally verifies the receipt bytes, complete retained-file manifest, required raw records, fixed case expectations, source/build binding digests, raw behavior, and actual owned fixture absence. Overall exit 0 requires both features to pass. Exit 1 means a failed or blocked journey; exit 2 is invalid CLI usage.

The tool only accepts `--output`. It does not accept arbitrary commands, case IDs, repositories or model-generated shell strings. Doctor has a 30-second outer limit. Each driver has a 180-second outer limit; its existing 90-second command-sequence budget does not bound all filesystem work. On timeout or wrapper SIGINT/SIGTERM, only its spawned direct child receives SIGTERM, then SIGKILL after five seconds if its exit was not confirmed. Pipe closeout is bounded by a further two seconds. The output records interruption, sent signals and direct-child exit separately; no clean process-tree claim is made. The wrapper never deletes a possibly live failed fixture.

A verified manifest establishes retained-file consistency, not an authenticated oracle or historical truth. Source/build digests check the driver-declared records and their consistency across both cases; the wrapper does not independently rehash all source/build files after closeout. Its own runner, scratch helper and driver/helper bytes are checked before and after the journey. Build digests alone do not prove a compiler invocation; retain the real build log separately. Direct child exits plus fixture removal do not prove all descendants terminated. Reports keep `descendant_termination:not_attested`. Actual scratch-directory emptiness is checked on success. Retained shallow listings and failed-case manifest hashes are closeout snapshots; unconfirmed descendants may still write. A late journey-level failure is displayed beside each independently verified row and does not erase the row’s earlier observation. The omitted drift/mixed/empty cases remain unrun. No J03, MethodBinding, provider, principal, native-host or runtime qualification is issued.

Run focused tests with `node --test scripts/method-verification-journey.test.mjs`. Offline fixtures test verifier rejection and stop behavior; they are not product observations. Actual journey evidence must come from a built checkout. Host-assisted and native-execution experiments can consume this tool later, with their own frozen inputs, permissions and budgets. Earlier native help failures are not retried by this command.
