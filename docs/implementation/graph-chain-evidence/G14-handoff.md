# G14 implementation handoff

Implemented G14 only. No daemon/broker/checkpoint/core/agents/AGENTS/user-doc/status edits, no commits/push/merge/deploy, no nested agents or Loops. Other actors' changes were left in place.

## Exact contracts

`packages/cli/src/graph-worker-manager.ts` exports `GraphWorkerManager`, `GraphWorkerManagerOptions`, `GraphWorkerProgramRegistration`, `GraphWorkerStart`, `GraphWorkerHandle`, `GraphWorkerExitEvidence`, `resolveGraphWorkerEntry`.

- Constructor options: `programs: readonly {id,modulePath,digest}[]`; optional `workerEntry`, `executable`, `heartbeatTimeoutMs` (5000), `startupTimeoutMs` (10000), `shutdownTimeoutMs` (1000), `terminationTimeoutMs` (1000), `requestTimeoutMs` (30000), `maxInFlight` (16, maximum64), `maxLogBytes` (16384, maximum1MiB per stream).
- Register a trusted self-contained ESM source file exporting `async run(context)`. `digest` is SHA256 of exact UTF-8 file bytes and MUST equal G08 `identity.compiledProgramDigest`. The manager reads/verifies/snapshots the file at registry construction. The child imports a data URL of exactly those verified bytes; subsequent file replacement cannot change execution. Do not register mutable imported application dependencies: bundle trusted program code into this snapshot. Installed engine/checkpoint versions remain independently pinned/checked at 1.4.15/1.1.5. No compiler is invented here.
- `start({binding,programId,input,resume?,authorize,register,action,checkpoint})` synchronously reserves the run, invokes registration, spawns asynchronously, and returns a frozen handle. Invalid identity/expired authority/duplicate-active-run throws before spawn. Registration/spawn failure returns a handle whose promises settle (internally observed to avoid unhandled rejection).
- `binding={scope,graphRunId,generation,owner,identity}` uses the full structural G08 identity (executionModel/durability/engine/checkpoint/template/registry/compiler/schema versions plus compiledProgramDigest/specHash/inputDigest). `input` is the original `StartGraphRequest`, not only `spec.input`; its digest is recomputed using G08's `computeGraphInputDigest`, and specHash is recomputed with the same domain/canonicalization. Trace metadata/idempotency key follow existing G08 business-digest semantics.
- `authorize(): {leaseExpiresAt:number}` must synchronously verify **current durable scope/run/full identity/generation/owner/revocation** and return current durable expiry. It runs before spawn, on each inbound message, before callback dispatch, after callback awaits, and during the watchdog. Manager independently rejects elapsed expiry, async authority, cancellation, old connection and replacement generation. Host owns durable acquire/renew/revoke; manager does not mutate the lease or create another FSM.
- `register(connection,binding): void` runs synchronously before init is sent. Use the same opaque connection object to register broker and the parent's dynamic checkpoint service. Async registration is rejected. Capture the persisted lease and trusted epoch/workspace/action registrations in the parent; do not take a whole-run broker admission permit.
- `action(connection,request,{signal})` receives the **per-worker AbortController signal**. Wire it directly to `broker.handle(connection,request,{signal})`. `checkpoint(connection,request)` wires to the authenticated checkpoint service. Both callbacks must retain their existing durable fencing. A dispatched callback may outlive the worker; cancellation/exit never releases its broker resources.
- Handle: `connection`, immutable `binding`, `ready: Promise<void>`, `result: Promise<GraphJsonValue>`, `exit: Promise<GraphWorkerExitEvidence>`, `cancel(reason?):void`, `stop(reason?):Promise<GraphWorkerExitEvidence>`, `logs():{stdout,stderr}`. Result is only a program outcome. Done and rejected invoke are NOT exit evidence.
- Exit evidence discriminant: `exited` includes run/generation/owner/pid/code/signal/confirmedAt/evidenceRef from `ChildProcess.exit`; `spawn_failed` includes an error and is NOT a stopped-worker receipt; `exit_unconfirmed` includes pid/error and cannot authorize takeover. After the stop deadline, TERM is followed by KILL and a bounded evidence deadline. The manager listens for `exit`, never waits for `close` or inherited log pipes. A very late exit after an `exit_unconfirmed` promise is not retroactively returned by that already-settled promise; parent must retain uncertainty and independently verify before issuing a receipt.
- Replacement requires the actual old child exit, strictly greater generation, identical scope/full identity/business-input digest/program registry ID. Parent must independently require executor stop/reconciliation and workspace isolation before authorizing the replacement.

`@osstack/graph/worker` preserves all previous SDK kernel exports and additionally exports `runGraphWorker`, `GraphWorkerClient`, and types `GraphWorkerProgram`/`GraphWorkerProgramContext`. Only direct execution with `--osstack-graph-worker` starts fd3 listener; importing prior exported symbols remains compatible.

Context: `{binding,input,resume?,action(request),checkpoint(request),signal,task}`. Input/binding/resume are recursively frozen. `task` is the installed public Functional task API. Runtime itself owns `entrypoint`, `RemoteCheckpointSaver` and invocation config `{durability:'sync', configurable:{thread_id:runId},signal}`. Resume is `{kind:'continue'}` (invoke null) or `{kind:'interrupt',value:GraphJsonValue}` (public Command resume; false preserved). No worker-supplied graph/module path is accepted. Source is parent-registry selected.

Protocol exports strict worker message/binding/identity/resume schemas plus `WorkerFrameDecoder`, `WorkerFramedTransport`, `encodeWorkerFrame`, `workerCanonical`, `freezeWorkerData`. New generated schema: `packages/protocol/schemas/graph-worker.schema.json`. fd3 uses 4-byte BE lengths with 8MiB raw cap checked before body allocation/JSON.parse. Sender writable backlog defaults to 16MiB+8 and has no extra queue. Client/host outstanding requests are bounded, client has a deadline, and host rejects request-number replay. Stdout/stderr are separately drained to bounded raw-byte tails; neither is interpreted as IPC.

## Parent integration requests / boundaries

1. Add `@osstack/graph: workspace:*` to CLI runtime dependencies/package lock as appropriate (outside G14 ownership). Published CLI default resolution uses **ESM `import.meta.resolve`**, because graph's worker export is import-only. Monorepo source tests use sibling `graph/dist/worker-entry.js` fallback. Build graph before source manager tests. A trusted explicit `workerEntry` is also supported. G14 does not edit CLI package metadata or daemon.
2. Dynamically register/delete the opaque connection in checkpoint/broker ports. Persist/verify `exited` evidence before creating `GraphStoppedWorkerEvidence`. Worker exit alone does not prove command/agent exit, reconcile effects, export artifacts or release locks/permits.
3. Any dedicated **pre-worker cancel / expired-owner / failed-spawn durable mutation** still belongs to parent/core. Do not fabricate an active owner or stopped receipt for `spawn_failed`. No second FSM or core workaround was added.
4. Architecture/process separation only, **not a same-user OS security sandbox**. Child gets no HOME/OSSTACK_HOME/NODE_OPTIONS/DB/socket environment or DB handle, and graph imports no core/CLI/DB library. Trusted JS can still use OS APIs as the same user. No hard package/artifact authenticity beyond trusted registry snapshot and installed pinned dependencies is claimed.
5. G17 daemon/broker/DB recovery chain remains parent work after G15/G16. G14 tests inject checkpoint callbacks; the dist smoke's two pure tasks prove the extensible context API, not command effects or C5. Existing graph saver tests independently exercise their accepted G13 SQLite fixture; they are not relabeled as production workers.
