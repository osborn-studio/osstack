**Verdict: changes_requested**

The DeepSeek profile preserves the accepted invariants from the Anthropic slice. The allowlist, the single 4 KiB atomic replacement, no tools, no subprocess, no retries, `redirect: 'error'`, the bounded body reader, env-only credentials, and the immutable owner binding are all intact. Provider and base URL live inside the digested config block at `packages/cli/src/graph-rpc.ts:299`, so an RPC caller cannot select them and any edit invalidates the grant. Usage mapping is correct: prompt and completion totals are taken once, with no re-adding of cache or reasoning counts. Stop proof still requires a fully parsed envelope with a single index-0 choice and no tool or function calls, and 5xx or malformed bodies stay unknown.

Three concrete defects are introduced.

**1. Writer request exceeds DeepSeek's max_tokens ceiling.** The adapter sends a fixed budget per role at `packages/agents/src/adapters/bounded-messages.ts:148`, and the DeepSeek request builder at `bounded-messages-provider.ts:53` forwards it unchanged. The writer budget is 32768. The linked create-chat-completion docs cap `max_tokens` at 8192 for non-thinking mode, and thinking is explicitly disabled here. DeepSeek answers an out-of-range value with HTTP 400. The profile then classifies that as a rejected request, so every writer invocation would end stopped-but-failed and the pilot cannot produce an edit. The reviewer sits exactly at the limit and would pass. Fix: clamp or pick the budget in the profile. A 4 KiB output cap never needs more than 8192 tokens anyway.

**2. `aborted` is accepted as a known terminal finish reason.** The enum at `bounded-messages-provider.ts:12` lists `aborted`. The documented set is stop, length, content_filter, tool_calls, and insufficient_system_resource. I could not find `aborted` in the create-chat-completion reference. The test at `bounded-messages.test.ts:168` bakes it in as a stopped failure, while the neighbouring test at line 175 asserts that an unknown reason must never prove stop. Those two tests contradict each other on principle. Either cite the doc line that defines `aborted` or remove it so it falls into the unknown bucket.

**3. Empty query or fragment bypasses the base URL check and corrupts the endpoint.** The guard at `bounded-messages-provider.ts:43` tests `base.search` and `base.hash`, which are empty strings for a bare trailing `?` or `#`. WHATWG serialisation still keeps that character in `href`. The endpoint builder at line 45 then appends the path after it, so `https://host?` becomes a POST to `/` with `/chat/completions` in the query string. The test at line 191 only covers non-empty query and fragment. Build the endpoint from `origin` plus a trimmed `pathname`, or reject any `?` or `#` in the raw string.

One pilot risk rather than a code defect. The message schema at line 14 requires `tool_calls` to be absent or an empty array. Some OpenAI-compatible servers emit `tool_calls: null`. If DeepSeek does that, every successful completion would fail schema parsing before the receipt is bound and would be recorded as unknown stop. Confirm the shape on the first real completion.

Everything else I checked holds: `authorization: Bearer` with no `x-api-key`, `stream:false`, `thinking.type=disabled`, `response_format json_object` with the word JSON present in the system prompt as the docs require, exact model equality, IPv6 loopback matched by the bracketed hostname, and the 400/401/402/422/429 rejection list only firing with a structured error body.
