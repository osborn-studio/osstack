# Explicit native candidate batches

The existing local `loop enqueue` and `loop run` entries accept `--candidate-policy /absolute/private/policy.json`. Nothing enables this mode automatically or installs configuration. Without the option, the original discovery, defaults, state, lease and execution routes remain unchanged. This feature uses the existing Loop CandidatePolicy and Task candidateBatch APIs, not another queue, controller or publisher.

The policy is strict JSON: a direct single-link user-owned 0600 file in a canonical user-owned 0700 directory, at most 64 KiB, with a private existing 0700 stateDirectory outside the workspace. Symlinks, aliases, unsafe modes, malformed UTF-8, unknown fields and file identity changes refuse with `LOOP_CANDIDATE_INPUT_INVALID` before lease acquisition or queue mutation. Validity of the runtime Git branch, actual queue and final frozen tree is checked by the existing Loop runtime, not claimed to be proved solely by reading this file.

```json
{"batchId":"related-feature-1","scopeId":"related-feature","branch":"codex/related-feature","policyFingerprint":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","environmentFingerprint":"bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb","testsFingerprint":"cccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccc","maxTasks":2,"scopePaths":["src/feature.ts"],"stateDirectory":"/absolute/private/candidate-state","profiles":{"local":["pnpm test"],"prepush":["pnpm typecheck"],"final":["pnpm test"]}}
```

These example fingerprints are placeholders, not measurements or evidence. The trusted operator must supply approved current policy/environment/test bindings. This CLI does not discover actual SDK/Codex identity or mint CI receipts from these fields. Policy commands remain trusted operator commands with the same authority as native `--execute`/`--verify`; the private file is not a sandbox.

```sh
osstack loop enqueue 'First related edit' --workspace /repo --id part-1 --candidate-policy /private/policy.json
osstack loop enqueue 'Second related edit' --workspace /repo --id part-2 --candidate-policy /private/policy.json
# Queue inputs must be part of the approved clean Git baseline before running.
osstack loop run --workspace /repo --candidate-policy /private/policy.json --source task_queue --worktree --agent approved-builder --reviewer approved-evaluator --verify 'pnpm test' --json
```

This first native qualification requires explicit `--worktree` and exactly one explicit `--source task_queue`. Other or repeated sources and omitted source refuse; the legacy default discovery sequence remains unchanged. The existing task scanner order is preserved, including task payload, context, evaluation and candidateBatch bindings. All discovered tasks must match the same bounded batch; unrelated/old records are not silently filtered into readiness. Queued Task bindings persist in the existing JSON format. Enqueue remains an enqueue operation, not a Git commit, authorization or acceptance operation.

The run continues through original observe/profile/adapters/review admission and repository lease, the live policy gate, unknown-execution containment and finally release/retain. Effective `--verify` commands, including persisted native defaults, are unioned into local, prepush and final policy commands. Existing Task evaluation, required reviewer and artifact gates remain enabled through the existing verifier. Candidate final checks still bind the complete base-to-candidate change range and exact clean HEAD/tree. A failed stage does not become readiness; append-only private claims are one-shot and are not automatically recovered or stolen. Queue files are not archived as acceptance.

Only a finite existing-flag subset is allowed with an actual candidate opt-in. State/markdown/goal overrides, daemon, polling/cycles/interval, checkpoint, governance exports, lessons/knowledge, self-improvement, archive, neat finalization, autonomy and unknown flags are refused before their side effects rather than silently dropped. Candidate runs also skip implicit probe observation, artifact export, lesson learning and neat finalization after engine return; their output fields remain absent on success, failure and recovery. This mode does not support arbitrary other native posthooks. Native profile/role choices, budgets, mandatory verifies/reviewers/checkers, artifact flags and worktree root remain supported. Repeated single-valued options refuse; repeated verifies, reviewers, checkers, role assignments and artifact path gates retain their native union semantics. Candidate flag values beginning with `--` refuse to avoid reinterpreting flat native control scans; flag-looking values on a noncandidate legacy route retain their old semantics.

Output explicitly remains `accepted:false`, `remoteCI:pending` and at most `final_preflight_ready`. No push, GitHub CI, merge, paid Provider inference, runtime installation or budget change follows this CLI run. Candidate mode does not call the implicit native knowledge/config hook; knowledge options are rejected and that feature is unavailable in this finite mode. A later independently approved delivery route must re-read full current mandatory CI at the final exact SHA. Native batching/API wiring is a finite local slice; full cost-control scope2/3 and measured savings are not established here.
