# Trusted candidate context at existing guarded delivery

The existing GuardedGitRuntime constructor accepts an optional trusted `candidateDeliveryContext` callback and an optional command-runner port. These are controller construction dependencies, not product-request flags, JSON policy, permission or queue fields. The normal CLI supplies no callback. Missing callback preserves the original delivery input and performs zero observer reads; an undefined qualification safely falls back to the original guarded delivery path after fresh policy checking. This source does not create a default SDK/Codex fingerprint producer or activate an installed runtime.

An enabled callback requires an independent live `assertPolicyUnchanged` dependency. It receives a fresh deep copy of workspace routing and budget, returns either undefined or a strict current three-fingerprint context, and is sampled before and after current metadata observation. Invalid values and exceptions refuse with a sanitized fixed error; changed fingerprints refuse handoff. Each fallback and final handoff rechecks the original live policy. Callback values are trusted controller qualification inputs, not permission or authenticated tool attestation.

`observeCurrentGreenCandidate` is stateless and read-only. It accepts no cached hint, validates a clean exact local branch/HEAD and the repository/remote relationship, and reads exact head/base refs, effective protection, a current OPEN PR with matching branch/base/head, and nonempty unique complete successful required checks. A well-formed remote candidate head different from local HEAD is a normal pending-push state and yields no hint; after final fresh policy checking, the original complete push/watch/protection path decides delivery. Legitimately missing target refs, missing/open-unqualified PR or unfinished/failed checks yield no hint; malformed, duplicate, extra, unknown or contradictory refs and scope refuse. The returned hint is passed to the same existing `deliverToGitHub` consumer with an independently re-sampled context.

The existing consumer still validates current binding, remote head/base twice, effective required protection, PR scope twice and complete current checks before its original SHA-bound merge port. A matching hint can avoid a duplicate push/checks watch; it cannot grant acceptance from cached green or bypass missing/cancelled/duplicate current checks. Delivery remains the existing merging API with its existing authority. This is not a new draft-only publisher and adds no merge action or automatic authority.

Local qualification uses the complete guarded runtime with private temporary local Git and SQLite fixtures and synthetic independent agent adapters. Every GitHub command and delivery/merge port is intercepted by a closed runner; unsupported or write commands in the observer throw. The delivery consumer tests intercept its original merge action rather than performing a real GitHub merge. Source mutants run a full valid baseline before demonstrating omitted second-context/unique-current-check guards produce a specific stale handoff or intercepted unsafe merge. No Provider is called.

Actual SDK/Codex identity qualification, independently measured environment/test fingerprints, installed runtime integration, production push/watch savings and full cost scope 3 remain pending. There is no runtime switch, budget change, release, remote CI, acceptance receipt or Wiki progress change in this slice. Full final exact-SHA CI and all existing gates remain mandatory before publication or acceptance.

The constructor command-runner port observes metadata only; the existing consumer retains its own default runner or trusted delivery port and independently re-reads all current facts. A test observer or hint therefore cannot attest production command identity. Native CLI/queue code is audited independently; this delivery slice does not replace that source review.
