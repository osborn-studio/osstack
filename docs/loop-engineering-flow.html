调用方

人 / Codex / CI / 平台

  • 提供 workspace、verify、execute、agent 等参数
→
Skill 包装层

  • SKILL.md 提供使用规则
  • scripts/*.sh 提供稳定入口
  • references/ 提供 schema 与集成说明

CLI 解析层

osstack loop

  • 优先使用当前仓库构建产物
  • 支持 OSSTACK_REPO
  • 支持 OSSTACK_CLI 或全局 osstack

@osstack/loop

  • 发现任务并执行循环
  • 调用 local command 或 agent adapter
  • 写入状态并返回退出码

二、核心循环：Discover → Plan → Execute → Verify → Iterate → State

1

Discover

从 tasks/*.json 或 git_diff 发现工作项。

  • loop enqueue
  • --source task_queue
  • --source git_diff
2

Plan

生成执行计划，决定执行者、迭代次数、停止条件和隔离方式。

  • --max-iter
  • --goal
  • --worktree
3

Execute

执行修复、生成代码、运行脚本，或调用 agent adapter。

  • --execute "cmd"
  • --agent codex-cli
  • --auto-agent
4

Verify

运行测试、类型检查、审查器或 checker，产生 pass/fail verdict。

  • --verify "pnpm test"
  • --reviewer ds-review
  • --checker ds-verify
5

Iterate

根据验证结果决定停止、继续下一轮，或升级给人类/Hermes。

  • success: stop
  • failure: continue / escalate
  • idle: optional stop
6

State

写出机器和人工都能读取的状态文件，并返回退出码。

  • LOOP-STATE.json
  • STATE.md
  • 0 / 1 / 2
审核重点：Skill 不复制 Loop 引擎，只负责把调用方稳定地接到 osstack loop。真实执行、状态机和验证逻辑仍由 TypeScript runtime 负责。

三、三种典型运行模式

Local 本地一次性循环

适合开发者、本地脚本、CI job。命令执行结束后返回退出码。

loop-engineering/scripts/loop-doctor.sh
LOOP_WORKTREE=0 \
LOOP_EXECUTE="node fix.mjs" \
LOOP_VERIFY="node test.mjs" \
loop-engineering/scripts/loop-run.sh
  • 默认 source: task_queue
  • 默认 verifier: pnpm test
  • 默认启用 --worktree

Daemon 后台托管循环

适合平台、dashboard、长期轮询、定时任务。session 可 list/status/stop。

node packages/cli/dist/bin.js serve
LOOP_GOAL="pnpm test" \
loop-engineering/scripts/loop-daemon-start.sh
loop-engineering/scripts/osstack-loop.sh list
loop-engineering/scripts/osstack-loop.sh stop loop_session_xxx
  • 支持 --interval-ms
  • 支持 --schedule "0 6 * * *"
  • 支持 daemon RPC status

Agent Agent / Reviewer 模式

适合需要模型写代码、审查 diff 或做独立验证的任务。

loop-engineering/scripts/osstack-loop.sh run \
  --source task_queue \
  --agent codex-cli \
  --verify "pnpm test"

loop-engineering/scripts/osstack-loop.sh run \
  --source task_queue \
  --execute "node fix.js" \
  --reviewer ds-review
  • --auto-agent 让 runtime 自动路由
  • --checker 是 reviewer/verifier 别名
  • 外部 adapter 可接入同一循环

四、输入、输出与状态边界

输入

  • workspace: LOOP_WORKSPACE 或 --workspace
  • 任务队列: tasks/*.json
  • 执行命令: LOOP_EXECUTE 或 --execute
  • 验证命令: LOOP_VERIFY 或 --verify
  • 隔离策略: LOOP_WORKTREE=1 或 --worktree
  • agent/reviewer/checker adapter ID

输出

  • LOOP-STATE.json: 机器可读状态
  • STATE.md: 人类审核摘要
  • tasks/archive/: 可选归档成功任务
  • stdout: loop summary 或 JSON summary
  • 退出码: 用于 CI 和平台判断结果

退出码语义

退出码 含义 平台建议
0 任务完成且验证通过。 标记成功，展示 STATE.md。
1 命令、配置、daemon 或环境错误。 作为运行错误处理，提示 doctor 或配置修复。
2 任务失败、验证失败或被升级。 作为工程任务失败处理，保留状态和日志供人工接手。
