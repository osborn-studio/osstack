## 2. Dependency / boundary audit findings

- Workspace graph is a DAG (no cycles). Only `supervisor` is `private: true`.
- **Kernel gap A — state repositories live in the product-private CLI**:
  run/task/event/approval *schemas* are in `core/src/state/schema.ts`, but the
  insert/read repositories are in `packages/cli/src/store.ts` (+ raw SELECTs in
  `daemon.ts`, `dashboard.ts`, `bin.ts`). An external consumer today cannot
  read run/event/proof state without `@osstack/cli`.
- **Kernel gap B — `@osstack/contracts` name is taken**: the existing package is
  the frontend/backend HTTP API contract checker (`ContractManifest`), unrelated
  to Doc 15's proposed kernel-schema package.
- **Kernel gap C — `loop` imports `@osstack/github`** (`discover.ts` branch
  steward scan): VCS coupling inside the layer Doc 15 wants VCS-neutral.
- Two disjoint `Task` shapes exist: `loop/src/types.ts` (file-queue Task) vs
  `core/src/state/schema.ts` `TaskRow` (DB row).
- Positive: nothing anywhere parses osstack CLI text as an API.
