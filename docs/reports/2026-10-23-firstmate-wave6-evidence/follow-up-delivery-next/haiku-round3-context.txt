1: # Public follow-up delivery ledger (O2a)
2: 
3: This increment implements local preparation, signed authorization, single-attempt dispatch, revocation and explicit reconciliation. No production transport, external target registry or authorization issuer is configured by default. Real public delivery remains **qualification_pending**. The built-in code never generates a signing key or treats a caller's actor name, approval boolean, receipt JSON, or task success as permission to send.
4: 
5: ## Review and authority
6: 
7: `follow-up-delivery prepare --repo /canonical/repo --default-tenant --input prepare.json` accepts a file containing `obligation_id`, `expected_obligation_revision`, `destination_ref`, `body`, and `idempotency_key`. The body is exact UTF-8 data, not instructions. The destination reference must resolve in a host-owned registry to a fixed GitHub account, repository, issue number and immutable target node ID and expected actor node ID. Arbitrary URL/recipient/provider fields in the request are rejected. Output contains the complete frozen envelope and digests for review.
8: 
9: Preparation is not authorization. An external trusted authority must review and sign `authorization_subject` plus a unique `grant_id`, `issued_at_ms`, `expires_at_ms`, and `max_calls: 1` using Ed25519 over `deliveryCanonical(body)`. Host trust registration restricts the public key's purpose, canonical repository, provider, destination references and maximum validity. No issuer or private-key handling is included in this increment. A signature made with a caller-generated unregistered key has no authority.
10: 
11: `follow-up-delivery authorize ID --repo /canonical/repo --default-tenant --revision N --grant grant.json` imports `{ body, key_id, signature }`. Grant fields bind the exact attempt, scope, provider/account, target digest, body digest and envelope digest. Dispatch rechecks signature, key registration, exact target, expiry and O1 obligation revision **inside the transaction that consumes authorization and records started**, immediately before the transport call. Host key removal or scoped revoke before this transaction prevents sending. Revocation after it cannot undo a call already in progress.
12: 
13: The CLI uses the existing daemon's authenticated local RPC. Root wiring must inject host registries; requests never select a transport or public key. Constructor `FollowUpDeliveryService(db, dbPath, options)` performs no I/O/migration. Methods are `follow-up-delivery.prepare|list|inspect|authorize|revoke|dispatch|reconcile`; all require an explicit canonical repository/default tenant. Writes use the existing DB lease. Same-user database/host-registry compromise is outside this boundary.
14: 
15: ## Results and recovery
16: 
17: `dispatch ID ... --revision N` performs at most one `sendOnce` call for that attempt. Missing transport, test transports without the host's explicit test flag, and adapters declaring automatic SDK retries yield `qualification_pending` without consuming the grant or creating started. Transport qualification labels are host configuration, not self-proving attestations; deployment must establish qualification separately.
18: 
19: A durable started row is written before the call. Disconnect, timeout, invalid receipt, process death or lost response leave started/`delivery_unknown` with consumed authority. Neither duplicate dispatch nor a new idempotency key for the same unresolved obligation can resend. A timeout's late response never silently overwrites the returned outcome. Abort is best effort and is not proof that the provider stopped.
20: 
21: `reconcile ID ... --revision N` calls only the registered provider's receipt lookup. The CLI cannot submit delivered=true or receipt data. A valid receipt must match provider, account, immutable target, pinned author node ID, body digest and attempt correlation; it stores bounded provider message/request IDs and its digest. Lookup failure or absence is still unknown. A future real provider must verify author, target and content from its authoritative response; this generic service cannot independently authenticate arbitrary adapter claims.
22: 
23: `revoke ID ... --revision N --reason TEXT` makes an unsent prepared attempt definitely_not_sent. If sending already started, it remains unknown. `inspect ID` and `list [--limit 1..50] [--after ID]` read scoped state. List uses UUID keyset order with explicit continuation, not a snapshot; concurrent inserts before the marker require a new scan. History is append-only. O1 `fulfilled_local` and external sending remain independent: delivery never resolves the promise.
24: 
25: Output is JSON, bounded to 64 KiB with terminal controls escaped and exact body preserved on parse. Prepare reserves room for the largest valid receipt before any send. Files must be regular, bounded, valid UTF-8, and not symlinks. `dispatch`/`reconcile` exit 0 only with `delivered` and `production_qualified`; test/sandbox evidence and uncertain/pending results exit 1, with the actual evidence still printed.
26: 
27: ## Qualification and rollback
28: 
29: Local tests exercise actual SQLite transactions and signatures, two connections, CLI-to-service invocation, a SIGKILL child immediately after committed consumption, response loss, timeouts and late completion, target/author/body mismatch, key removal, revocation, scope, stale revisions and bounded outputs. Fake send counts prove local invocation behavior only; no real message is sent and no real provider delivery guarantee is claimed.
30: 
31: O2b must separately supply a reviewed provider adapter, explicit human target/body approval issuer, pinned credentials/account, disabled SDK retries, real sandbox receipt lookups and controlled disconnect/crash qualification. Until then retain empty production registries. To roll back, disable the command/provider registration and retain migration 45's ledger. Do not drop unknown attempts, reset grants or down-migrate a serving DB to enable retries. Outstanding uncertainty requires reconciliation or operator investigation outside automatic sending.
32: 
33: Revocation records a logical nondecreasing ledger time when the host clock regresses; it remains available to remove authority even then. Grant validation and dispatch still use strict wall-clock checks. Once consumed, grant status stays consumed permanently; a later revocation is a separate immutable transition event, not a rewrite of consumption. If revocation or reconciliation races an in-flight send, the stale sender does not overwrite the newer uncertainty state. An explicit authoritative lookup can subsequently prove delivery.
34: 
35: A completed delivery does not authorize another message. A later update for the same obligation needs a new prepared envelope, a new attempt ID and a newly reviewed signature. Unresolved attempts block this path. An expired or removed-key grant on a prepared attempt is safely unsent but continues to reserve its obligation; inspect and explicitly revoke it before preparing a replacement. There is no automatic expiry cleanup or resend.
36: 
37: ## Daemon shutdown contract
38: 
39: The host must stop accepting new calls, track every `service.handle(...)` promise and await their settlement before closing the database. Transport and lookup waits have a logical maximum of 30,000 ms each (default 5,000 ms); the final ledger transaction must also finish before the handle settles. Do not close the DB merely because a shorter shutdown deadline elapsed. Uncooperative asynchronous transports can remain alive after abort, but their late fulfillment/rejection has no database continuation: the already-settled race discards it. A blocking synchronous adapter or synchronous DB lock cannot be preempted by a JavaScript timer; host adapters must avoid blocking the event loop. No background timer initiates another dispatch or reconciliation.
40: 
41: ## Durability and clock boundary
42: 
43: O2 writes temporarily require `journal_mode=WAL` and verified `synchronous=FULL`; on macOS they additionally enable and verify `fullfsync`. The synchronous transaction commits before the provider call, then restores the connection's prior settings without an intervening await. Other OSStack DB behavior is unchanged. This follows SQLite's documented [WAL durability settings](https://www.sqlite.org/pragma.html#pragma_synchronous) and [macOS fullfsync flag](https://www.sqlite.org/pragma.html#pragma_fullfsync). SIGKILL tests prove process-crash recovery, not physical power-cut or storage-device qualification; the filesystem/VFS/device must honor synchronization, which remains part of deployment qualification.
44: 
45: Migration 45 also retains the maximum valid clock observed by O2 writes. A rejected expiry check persists its observation before returning, so a later clock rollback cannot revive that known-expired grant, even after service restart. Admission rejects a clock below this durable record. Post-send evidence and revocation use logical nondecreasing ledger timestamps, so a regressed clock does not prevent recording an irreversible result or removing authority. This is not an independent trusted time service: time never observed by the ledger cannot be reconstructed after downtime, and host-clock integrity remains a deployment requirement.
46: 
47: Read/list/revoke/reconcile match the original stored canonical path string without requiring its directory to remain present; they cannot rebind the record to a moved directory or follow a new symlink. Prepare/authorize/dispatch still require the live canonical directory. Thus a moved/deleted repository can be inspected and its old authority removed using its exact historical scope. Body controls are permitted as exact data but escaped in review JSON; a future provider may reject them and must not silently normalize approved text. Pagination UUID case is normalized before comparison.

41: export interface OpenDbOptions {
42:   /** Absolute path to the SQLite file (parent dir must exist). */
43:   path: string;
44:   /** When false, opens read-only. */

50: /**
51:  * Run a free-space check against the filesystem holding `path`. Throws
52:  * DiskFullError if below threshold; otherwise returns free byte count.
53:  * Skips the check (returns Infinity) if statfsSync is unsupported on the
54:  * platform — better to allow writes than to crash a daemon on a kernel quirk.
55:  */
56: export function preflightDiskSpace(
57:   path: string,
58:   minFreeBytes: number = DEFAULT_MIN_FREE_BYTES,
59: ): number {
60:   let stats: { bsize: number; bavail: number };
61:   try {
62:     stats = statfsSync(dirname(path));
63:   } catch {
64:     return Number.POSITIVE_INFINITY;
65:   }
66:   const free = Number(stats.bsize) * Number(stats.bavail);
67:   if (free < minFreeBytes) throw new DiskFullError(path, free, minFreeBytes);
68:   return free;
69: }

71: /**
72:  * Open the osstack state database, apply pragmas, and run pending migrations.
73:  * Caller owns the lifetime — pair every openDb() with a db.close() in shutdown.
74:  */
75: export function openDb(opts: OpenDbOptions): Database.Database {
76:   const { path, readwrite = true, minFreeBytes = DEFAULT_MIN_FREE_BYTES } = opts;
77:   if (readwrite) preflightDiskSpace(path, minFreeBytes);
78: 
79:   const db = new Database(path, { readonly: !readwrite });
80: 
81:   try {
82:     // Refuse an unsupported schema before changing journal mode or running DDL,
83:     // including read-only inspection. A failed open never escapes with a live handle.
84:     assertSupportedVersion(db.pragma("user_version", { simple: true }) as number);
85:     assertMigrationLineage(db);
86:     // Pragmas are applied per-connection in SQLite. Apply on every open.
87:     if (readwrite) db.pragma("journal_mode = WAL");
88:     db.pragma("synchronous = NORMAL");
89:     db.pragma(`cache_size = ${PAGE_CACHE_KIB}`);
90:     db.pragma("foreign_keys = ON");
91:     db.pragma("busy_timeout = 5000");

93:     if (readwrite) runMigrations(db);
94:     return db;
95:   } catch (error) {
96:     db.close();

98:   }

101: // This schema is table-additive. Derive expected table introductions once;
102: // a future DROP/RENAME migration must also update this lineage contract.
103: const tableIntroductions = MIGRATIONS.flatMap(migration =>
104:   [...migration.sql.matchAll(/^\s*CREATE\s+TABLE(?:\s+IF\s+NOT\s+EXISTS)?\s+([a-zA-Z_]\w*)\s*\(/gm)]
105:     .map(match => ({ name: match[1]!, version: migration.id })));
106: 
107: /** Reject pure or mixed unreleased Graph schemas before application pragmas or
108:  * DDL. SQLite may itself checkpoint an abandoned WAL on close; logical ledger
109:  * content and user_version must remain intact for the original binary. */
110: function assertMigrationLineage(db: Database.Database): void {
111:   const current = db.pragma("user_version", { simple: true }) as number;
112:   const actual = new Set((db.prepare("SELECT name FROM sqlite_master WHERE type='table'").all() as { name: string }[]).map(row => row.name));
113:   // Experimental Graph or Attention tables must never be migrated as released main.
114:   const experimentalTable = (name: string) => name.startsWith("graph_") || name.startsWith("attention_") || name === "daemon_owner";
115:   if (current < 25 && ![...actual].some(experimentalTable)) return;
116:   const expected = new Set(tableIntroductions.filter(table => table.version <= current).map(table => table.name));
117:   if ([...expected].some(name => !actual.has(name))
118:     || [...actual].some(name => experimentalTable(name) && !expected.has(name))) {
119:     throw new Error("GRAPH_EXPERIMENTAL_SCHEMA_CONFLICT: preserve this home and reconcile with its original build; do not reset user_version or reuse it for the integrated runtime");
120:   }
121: }

123: function assertSupportedVersion(current: number): void {
124:   if (current > CURRENT_SCHEMA_VERSION) {
125:     throw new Error(`Migration state inconsistent: user_version=${current}, expected=${CURRENT_SCHEMA_VERSION}`);
126:   }
127: }

129: /**
130:  * Apply pending migrations idempotently. `user_version` PRAGMA tracks progress.
131:  * The version pragma guarantees forward-only application. Many migrations
132:  * contain non-idempotent CREATE/ALTER statements; never reset user_version.
133:  */
134: export function runMigrations(db: Database.Database): void {
135:   const currentRow = db.pragma("user_version", { simple: true }) as number;
136:   let current = Number(currentRow);
137:   assertSupportedVersion(current);
138:   assertMigrationLineage(db);
139:   for (const m of MIGRATIONS) {
140:     if (m.id <= current) continue;
141:     db.exec("BEGIN");
142:     try {
143:       db.exec(m.sql);
144:       db.pragma(`user_version = ${m.id}`);
145:       db.exec("COMMIT");
146:       current = m.id;
147:     } catch (err) {
148:       db.exec("ROLLBACK");
149:       throw err;
150:     }
151:   }
152:   if (current !== CURRENT_SCHEMA_VERSION) {
153:     throw new Error(
154:       `Migration state inconsistent: user_version=${current}, expected=${CURRENT_SCHEMA_VERSION}`,
155:     );
156:   }
157: }

159: /**
160:  * Run a function inside a transaction with preflight. Use for any write path
161:  * called from the daemon hot loop. Wraps better-sqlite3's transaction() so
162:  * disk-space errors fire BEFORE BEGIN, not mid-transaction.
163:  */

165:   db: Database.Database,
166:   path: string,
167:   fn: (db: Database.Database) => T,
168:   minFreeBytes: number = DEFAULT_MIN_FREE_BYTES,
169: ): T {
170:   preflightDiskSpace(path, minFreeBytes);
171:   const tx = db.transaction(fn);
172:   return tx(db);
173: }
