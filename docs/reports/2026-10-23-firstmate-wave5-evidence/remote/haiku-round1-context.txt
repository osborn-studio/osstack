1: # R1 remote home read-only projection
2: 
3: ## Delivery and ownership
4: 
5: This increment implements an explicit, pinned SSH stdio reader of an already running OSStack home. It does not start a daemon, open a database, execute agents, forward arbitrary RPC, or claim remote-host qualification. The root integration owns lazy CLI routing; these modules own protocol, exporter, client, and focused tests.
6: 
7: `remote-home inspect --registry FILE --sha256 HASH --alias NAME [--limit 1..50]` loads a bounded owner-only regular canonical registry file. Each entry pins hostname/port/user, an Ed25519 host public key, an explicit private identity file, home ID, daemon protocol, exporter registry digest, and scope alias. The local registry digest is also pinned by the operator. Registry changes require explicit repinning.
8: 
9: `remote-export --stdio` reads only host-provided `OSSTACK_REMOTE_EXPORT_REGISTRY` and `OSSTACK_REMOTE_EXPORT_SHA256`. Its registry pins home ID, daemon protocol, explicit canonical same-UID socket, and canonical repository scopes with explicit default tenant. Requests cannot replace these paths. SSH invokes exactly the literal `osstack remote-export --stdio`; deploy it with a restricted SSH account/forced-command wrapper that sets the registry environment and does not permit port forwarding. The client does not install or modify SSH configuration.
10: 
11: ## Wire and authorization
12: 
13: Version 1 uses UTF-8 JSON behind a four-byte big-endian length prefix, at most 65,536 bytes including header. A connection has exactly two sequential exchanges: hello (nonce, protocol, home, server-registry digest, scope), then snapshot (channel token, sequence 1, limit). The exporter grants a random connection-local read-only token only after matching the registry and current daemon identity. Strict schemas reject every other method and unknown field. Tokens do not authorize generic local RPC and are never stored or printed.
14: 
15: The exporter sends only fixed local `deployment.identity` and `worker.list` RPCs. Identity is checked before the grant and both before/after the snapshot; home/protocol/generation changes fail closed. Socket ownership/canonical path/inode are checked around reads. The worker response must match the canonical scope and expected scope digest. Projection removes repository paths, opaque local view IDs/cursors, prompts, logs, provider IDs and credentials. Per-row references are snapshot-local; they cannot be used as stable worker identities or cancellation targets.
16: 
17: Each wire response binds nonce, home, instance generation, registry digest, scope, protocol and sequence. Snapshot payload is SHA-256 hashed as evidence of the bytes/fields observed, not independent proof that the server's assertions are true. SSH host authentication and server authorization remain the deployment trust boundary. A home ID/nonce/hash is not standalone authentication.
18: 
19: ## Limits, uncertainty and freshness
20: 
21: At most one in-flight request, one page of at most 50 source views, two frames per direction, and bounded stderr; no reconnect, replay, action retry or local fallback. A truncated page explicitly reports incomplete and `has_more`; no cursor is exposed in this first increment. A complete empty page proves only that this query returned no eligible source views, never that the home is healthy. Session/run rows can describe the same worker; Graph and unbound runs remain excluded.
22: 
23: The client reports local monotonic round-trip duration and local receipt time. Remote timestamps and source freshness are untrusted observations and never prove liveness. Negative/future source clock relationships are reported as unknown. The view is a point-in-time observation, not a durable cache or live stream. Timeouts, disconnects, framing/protocol/identity errors produce an allowlisted unknown result without reusing stale observations.
24: 
25: ## Tests and release qualification

1: # Read a remote home without remote control
2: 
3: This optional command projects a single bounded page of Session and bound-run status from an already running remote OSStack daemon. It does not send messages, start/cancel/resume workers, open a remote database, install a daemon, or register a general RPC relay. Graph, unbound runs, logs and incremental events are not supported.
4: 
5: The deployment operator must provision an SSH account/key with a forced command or equivalent restrictions. That wrapper executes the fixed literal `osstack remote-export --stdio` with `OSSTACK_REMOTE_EXPORT_REGISTRY` and `OSSTACK_REMOTE_EXPORT_SHA256` already set. It must disable forwarding and interactive shell access. The exporter cannot enforce the SSH account's other authorized commands; its read-only channel token grants only one snapshot. No account or remote host is automatically provisioned.
6: 
7: Create an owner-only (`0600`) regular registry at an absolute canonical path on the exporter host. All configured paths must be canonical and cannot be symlinks. Example (replace every placeholder before use):
8: 
9: ```json
10: {
11:   "version": 1,
12:   "home_id": "home_0123456789abcdef0123456789abcdef",
13:   "daemon_protocol": 1,
14:   "socket": "/absolute/serving-home/daemon.sock",
15:   "scopes": [{"alias":"project","repo_path":"/absolute/project","default_tenant":true}]
16: }
17: ```
18: 
19: The home ID and daemon protocol come from the running home's `deployment.identity`, not from repository names or a guessed home path. Compute the SHA-256 of the exact registry file bytes and pin it in the wrapper environment. The exporter verifies that its configured socket is canonical and owned by the same OS user, and that the daemon identifies the pinned home. This local socket trust is not independent peer-credential attestation. Owners who can replace their own binaries/configuration or daemon remain trusted.
20: 
21: On the reader machine, create another `0600` canonical regular registry:
22: 
23: ```json
24: {
25:   "version":1,
26:   "homes":[{
27:     "alias":"dev",
28:     "host":"example.test",
29:     "port":22,
30:     "user":"reader",
31:     "host_key":"ssh-ed25519 BASE64_PUBLIC_HOST_KEY",
32:     "identity_file":"/absolute/private/readonly_identity",
33:     "home_id":"home_0123456789abcdef0123456789abcdef",
34:     "daemon_protocol":1,
35:     "registry_sha256":"EXPORTER_REGISTRY_SHA256",
36:     "scope":"project"
37:   }]
38: }
39: ```
40: 
41: The host public key is a full Ed25519 public key, verified independently with the host operator. A key retrieved on the same untrusted connection is not a trustworthy pin. The private identity file must also be an owner-only canonical regular file; it is passed directly to OpenSSH and never printed or read into an application payload. Only DNS names/IPv4-style host strings are accepted in this first version; IPv6 literals and custom SSH options are not supported. SSH must be available at `/usr/bin/ssh`.
42: 
43: Run `osstack remote-home inspect --registry /absolute/client.json --sha256 CLIENT_REGISTRY_SHA256 --alias dev --limit 50`. The reader ignores user SSH config and agents, creates a restrictive temporary known-hosts file containing only the pinned host key, and disables proxying, forwarding and connection multiplexing. The remote command is constant; registry fields are never interpolated into a shell command. Configuration/key changes require explicit digest/key repinning. The home pin and exporter registry digest are independently checked after SSH transport authentication.
44: 
45: Output is JSON, at most 64 KiB. `status: observed` means the bound response was received; it does not mean the home is healthy. `snapshot.complete: false` and `has_more: true` mean only the first page was observed. Exit status is nonzero for incomplete or unavailable observations. No continuation cursor is exposed yet. Empty results still describe only this scope's eligible source views. Session and run rows may describe the same worker.
46: 
47: Rows contain metadata and snapshot-local `observation_ref` values. These references are not stable worker IDs or action handles. The output omits private repository paths, local opaque worker IDs/cursors, prompt/log/decision text and provider-native IDs. A source's completed status is an observed stored fact, not proof that a provider process has stopped. `process_liveness` remains unknown.
48: 
49: `received_at_ms` is the reader's local receipt time; `round_trip_ms` uses a local monotonic clock. Remote timestamps and source freshness remain unverified. `remote_clock` merely compares the remote sample time with the local clock; it does not synchronize clocks or establish freshness. Re-read explicitly for a new observation. A timeout, disconnection or binding error returns `status: unknown` and no stale snapshot. It never falls back to the local home or retries an action.
50: 
51: The evidence digest hashes the canonical parsed snapshot fields (excluding the digest itself), binding nonce, generation, scope, registry and row metadata. It detects accidental/tampered binding within the authenticated channel; it does not independently attest server truth. The channel token is random, connection-local and never printed. It is not a general OSStack credential.
52: 
53: Local isolated child-process tests and a real running local daemon qualify the wire and socket implementation. A real remote host has not been supplied: two-host SSH authentication, account restrictions, network failure behavior and key rotation are **pending qualification**. Every result preserves `qualification: remote_host_pending`. No general remote-action or plugin ecosystem qualification is implied.
