## 调用真实性

完成两次显式指定 `claude-fable-5-1` 的 Claude CLI 调用，两次 `is_error=false`，实际 `modelUsage` 均包含该模型。第一轮允许 Read/Grep/Glob 只读核查两个仓库，禁用 Bash/Edit/Write、slash commands 与 MCP；第二轮禁用所有工具，提供主报告草稿和对第一轮的质疑，做对抗性审阅。第二轮元数据还记录 CLI 辅助 Haiku 调用，不能把它说成另一位独立研究者。

第一轮用时约 347 秒、56 个调用轮次；第二轮约 131 秒、1 个轮次。元数据记录的是调用信息及估算用量，不是用户实际账单。原始输出保存在 [第一轮](2026-09-11-graph-engineering-evidence/claude-round1.md)、[第二轮](2026-09-11-graph-engineering-evidence/claude-round2.md)，不把模型判断计入测试通过数。

## 两轮的主要分歧

Fable 第一轮建议：先给文件队列 Task 加显式 depends_on，再做串行拓扑执行，延后知识图与因果事件。Codex 的不同判断是：目前并未检查真实任务日志来证明依赖错序是高频痛点，先修改控制路径可能过早，应先用窄的跨源联查检验是否存在需求。

第二轮没有否定报告交付，但指出“只读解释任务不能开始”超出了现有数据支持。最终收紧为：P0 仅提供关系清单、影响提示和已有阻塞原因转述；普通关系不能产生 blocked 标签。是否增加任务依赖字段，取决于实际案例。保留 Fable 对直接做任务依赖的倾向，没有宣称两模型完全一致。

## 已落实的修订

| 意见 | 最终处理 |
|---|---|
| P0 不能从普通链接推导任务阻塞 | 已限定 blocked 的权威来源，缺失任务依赖时明确回答未记录 |
| 合并依赖类别会丢失语义 | 增加 typed probe：44 条 dependencies、1 条 devDependencies，并分别记录闭包；保留旧粗粒度结果作为过程证据 |
| “只读”缓存可能误用控制面迁移 | G1 不新增 schema，不写业务表，要求无迁移／readonly 读取；缓存仅用内存或独立可删除文件 |
| 冲突与权威未充分定义 | 权威按具体断言区分；冲突并列返回，不覆盖；历史只能来自源记录 |
| 活动计划与每轮发现冲突 | 冻结节点集合，计划外同 repo 自动写任务延后；不长期占写锁；每次领取重查基线，外部变化触发失效／重验 |
| 可能重复 collaborator 阶段状态 | 核查 SessionContinuationRequest 和 session-collaborator；复用 session/turn/version 与终态，不把图就绪当授权 |
| 自选开发集不能证明收益 | 增加预先冻结、独立留出、真值来源和非构建者测量；无增益即停 |
| 不能泛称所有事件缺少关系 | 限定为已核查路径；未检查全部 payload；来源关系不等于因果证明 |

## 没有照单全收的部分

1. **先抽通用 Kahn。** 两份算法确有重复，但现有差异和测试是业务资产。只有新增消费者明确需要公共契约时再提取，不为本次研究额外重构。
2. **加一个 caused_by 就解决归因。** 显式引用方便追踪，但现有 payload/source refs 也可能承载关系；任一种指针均不证明因果。最终采用实际消费版本、可观测证据与诊断假设分开表达。
3. **superseded_by 一列就足够。** 只能表示替代链，不能补回有效时间或已缺失历史。最终不把这次研究转成 memory schema 迁移。
4. **package.json 一律是派生来源。** 不采纳这种笼统划分。它对“声明了依赖”是权威，对“运行时实际消费”不是；闭包是派生。
5. **devDependency 只影响构建／测试，绝不影响运行。** 不能绝对化，构建产物可能间接改变交付。最终保留类别并限定可推出的语义。
6. **省略 tenant 的既有 API 必然是漏洞。** 已确认该 API 有显式 legacy 全租户行为；本轮没有完成调用方授权审计，不能直接宣称存在泄漏。新图入口必须显式约束 scope，这是明确集成要求。

第二轮原始输出的“接受四点”段落还出现了自相矛盾的压缩表述；以上取舍依据实际源码与具体论点，不以模型自称同意为准。

## 交付标准

Fable 第二轮判断为“研究建议可交付，集成收益仍待实验”。Codex 已根据其具体意见修订主报告，并重跑依赖提取、检查来源锚点和文档引用；没有把修改后的全文再提交第三轮模型评分。停止研究的依据是决策所需来源、缺口、反例、实现边界和可推翻实验已经明确，剩余问题需要真实工作负载实验，而不是继续增加模型意见。

最终完成的是研究报告与可核对证据。没有安装图后端、修改运行代码、变更默认控制面数据库、启用新调度行为、提交或推送仓库。
