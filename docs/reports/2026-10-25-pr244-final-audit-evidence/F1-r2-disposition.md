# F1 second closure: actual uncertainty containment

The initial prearm fix passed the original replay property, but the first model review found further live-worktree cleanup and goal classification gaps. Both are fixed. Its NEEDS_FIX raw result and initial failing test logs remain preserved.

* Before execution admission, a fixed JSON containment record is exclusively created and fsynced, including parent directory entries. Any partial/existing entry blocks execution. No new write is needed after detecting uncertainty. A state write failure, exception or crash leaves that prearmed record. Record removal requires completed cycle state persistence and no stop/integrity uncertainty.
* Containment is now workspace-scoped, not state-file-scoped. Git workspaces use their canonical real Git-directory identity and a private `osstack-loop-containment` directory inside that metadata directory. Git discovery removes every inherited GIT_* variable. Canonical workspace subdirectories and alternate state paths cannot bypass the same repository record. Linked worktrees have distinct Git metadata and are distinct candidates. Normal `git clean -fdx` cannot delete the metadata record, and the record is not a candidate changed_path/diff. No review allowlist was weakened.
* A non-Git workspace uses a fixed `.osstack-loop-containment.json` in its canonical workspace root, independent of explicit state-file path. Non-Git workspaces have no applicable git-clean operation. Deleting the entire workspace/trusted metadata is not a safe reset protocol. Same-uid hostile mutation or changing workspace identity is not an isolation boundary.
* executeLegacyImplementation, verifyRun (task and final preflight), goal commands and publish invocation rejections pass through awaitStopSensitive. A rejected promise cannot be treated as evidence of no launch: the flag becomes unconfirmed before finally can clean the worktree. The live-child rejection regression proves the child is still live and the worktree and branch remain; the test itself explicitly terminates its owned child afterwards.
* Goal termination/cancellation stop_confirmed=false is classified and cannot clear containment or be reported as a passing goal. Verifier command/artifact unknown stops now terminate verification immediately and emit verify.adapter_stop_unconfirmed (separately implemented/tested by graph agent); runtime maps that rule to its quarantine. All supplied verifier source is current.
* Restart reports `execution_containment_pending`, not idle/completed; containment has its own field and does not falsely label an integrity-only marker as a physical-stop observation.

Publisher qualification: the existing optional external publisher interface returns stdout/exitCode only; runCommandReal waits for child close and has no timeout/cancel/termination field. This patch retains containment on a rejected publisher promise, but it does not certify publisher descendant-group stop on a normally fulfilled publisher result. Such host callbacks remain trusted integrations with their existing finite completion contract; no new physical-stop guarantee or automatic retry product is claimed for them. Arbitrarily detached subprocesses and trusted hooks that return before their work is complete remain outside the executable/verifier process-group stop contract. This scope is explicit, rather than synthesizing a stop receipt.

Tests now cover executor rejection with an actually live child and retained worktree, a marker assertion before the first launch, different-state restart, goal unknown stop, git clean followed by verifier unknown and state ENOSPC, directory-fsync failure, and inherited Git redirection/subdirectory aliases. The previous static reviewer did not execute these tests. F1-r2-validation.json records host command exit codes and hashes; final source hashes are bound by the review manifest. P3 over-conservative ancestor directory fsync is retained: inability to sync is a fail-closed availability limitation. Confirmed-normal-state exactly-once durability remains pre-existing and unclaimed.
