# Parent F1 durable stop containment

The lifecycle lease is optional and its retain interface returns void. Generic LoopEngine safety does not rely on it being durable. Before any admitted task or goal command, the engine creates an exclusive `<state-json-path>.stop-unconfirmed.json` record, syncs its contents and all parent directory entries, and only then invokes external work. Failed creation/write/fsync aborts admission; an empty or malformed leftover entry still blocks restart. The marker is intentionally armed before detection, so a failure or crash after detecting unknown stop requires no new disk write to remain contained.

After executor or verifier unknown stop, the existing in-memory and completed-task fields remain and self-improvement is skipped. Marker removal requires a completed cycle state write and no unknown stop (plus any independently imposed contaminated-candidate restriction). Crash, state write failure, unknown stop or an exception leaves the prearmed record. A new engine checks existence before discovery/execution and never infers physical stop from a PID, a timeout, record age or absent result. No automatic rearm/reset is provided. This conservative record can block after known-stopped work if state persistence failed; recovery requires separate operator investigation rather than silent marker deletion.

The key is the configured state file identity. Same-uid hostile deletion/replacement, selecting a different state path to bypass containment, and unsupported/dishonest filesystem durability are not an isolation guarantee. Directory sync errors refuse admission. The record is not a physical-stop receipt. Ordinary successful cycles remove it and preserve prior repeat-cycle behavior. F3 verifier read-only/candidate contamination is owned and separately reviewed by graph agent.

Focused regression covers unknown verifier timeout followed by failing writeLoopState (ENOSPC simulation), no resulting state JSON, then restart executing no work; prearmed interrupted record with no state JSON; failure while writing or fsyncing initial record; explicit normal release. Initial integrated log includes five F3 fixture failures retained for transparency; targeted F1 tests pass after supplying a Git workspace required by new F3 snapshots.

The new prearm record is actual fixed JSON with a .json extension, so it does not trigger the existing Kimi review binary-extension boundary. No review-boundary exemption or widened allowlist is added. Any existing entry still blocks regardless of parseability. This new filename has never been shipped; the intermediate non-JSON filename existed only in this development attempt.
