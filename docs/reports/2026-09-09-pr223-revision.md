# PR 223 revision: live-pilot failure isolation

The owner requested changes before approval. At inspection, PR 223 had green CI and no published reviewer comments. These are additional self-review findings; any unpublished owner requirements are still requested separately.

## Fixes

The earlier fixture changed `OSSTACK_HOME`, opened its database and wrote initial evidence before entering the cleanup block. Opening/writing failures could leave the overridden environment or an open DB behind. The final evidence write also preceded database close/environment restoration, so a failed final write skipped both cleanup operations.

A test-only resource scope now covers open and initial write, closes the acquired DB before final evidence persistence, restores both previously set and previously absent home/socket values, and keeps original and cleanup failures in order using AggregateError. A close failure is included in the final failure receipt. A failure to persist that receipt still fails the test. Generated artifacts are deliberately retained: deleting the directory on a failed open would destroy the documented failure evidence. An open function that throws without returning a handle cannot have that nonexistent handle closed by the scope; the error is retained and environment restored.

The observation wrapper now preserves optional runtimeIdentity with the original receiver, forwards task/signal and original events, and closes the provider iterator if observation fails. It does not invent missing optional methods. This is a one-shot AgentAdapter decorator, not a proxy for unspecified native/session internals.

The launcher removes inherited OSSTACK_SOCKET from its child environment so a fresh home cannot still point to a serving socket. It does not change the parent environment. New process-level tests use a fake pnpm, never an actual provider, and cover success, nonzero child exit, spawn failure, precise argv, fresh-home creation/cleanup and socket isolation.
