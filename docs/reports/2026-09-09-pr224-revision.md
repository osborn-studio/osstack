# PR 224 revision: preserve command intent

The owner requested changes before approving PRs 223 and 224. At inspection, both heads had green CI and neither PR had published reviews, conversation comments or inline review comments. The owner was asked for any unpublished requirements while code review continued. The findings below are our additional review findings, not attributed to a nonexistent GitHub review.

## Reproduced defects and fix

- Publish silently accepted candidate-only options (`--namespace`, `--reuse-scope`, `--allow-dirty`). A caller could believe a namespace/scope constraint was applied when the companion never received it. Parse options against the selected command's allowlist and reject unsupported options before child/Git work. Candidate still forwards its valid namespace and reuse scope through the existing tested contract.
- Both candidate/publish ignored extra asset arguments. Reject them before source resolution or child execution.
- Candidate namespace parsing truncated extra segments (`organization/acme/extra` became `organization/acme`). Validate the complete namespace using the existing lowercase logical namespace grammar before splitting it.
- Unrecognized/error child status with exit 0 and positive evidence flags could produce `status:error` with `delivery:api_verified`. Only the recognized published status can carry a verified delivery classification; otherwise retain companion booleans, return unknown delivery and a stable failure reason.

The added regression cases produced **11 failures** against the previous implementation; after repair all **55 Hub tests** pass. Existing tests confirm valid candidate arguments are still forwarded and unsupported surfaces never start the child. API version evidence remains companion-reported, not digest attestation.
